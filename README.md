# Firelocks Service

A standalone NestJS + TypeScript service that acts as a proxy to the Fireblocks Create Transaction API.

## Overview

This service provides a REST API endpoint that forwards transaction creation requests to the Fireblocks API, handling authentication, validation, and error responses in a clean, well-structured manner.

## Features

- ✅ REST API endpoint: `POST /transactions`
- ✅ Input validation using `class-validator` and `class-transformer`
- ✅ Fireblocks API authentication (JWT signing structure)
- ✅ Comprehensive error handling
- ✅ Environment variable configuration
- ✅ Unit tests with Jest
- ✅ TypeScript with strong typing throughout
- ✅ NestJS best practices (modules, controllers, services, DTOs)

## Tech Stack

- **Runtime**: Node.js LTS
- **Framework**: NestJS
- **Language**: TypeScript
- **Package Manager**: npm
- **Testing**: Jest
- **HTTP Client**: @nestjs/axios (Axios-based)

## Getting Started

### Prerequisites

- Node.js LTS (v18 or higher)
- npm

### Installation

1. Clone the repository:
```bash
git clone git@github.com:nehilor/firelocks-service.git
cd firelocks-service
```

2. Install dependencies:
```bash
npm install
```

3. Create a `.env` file based on `.env.example`:
```bash
cp .env.example .env
```

4. Configure your environment variables in `.env`:
```env
FIREBLOCKS_API_KEY=your-api-key-here
FIREBLOCKS_API_SECRET=your-api-secret-here
FIREBLOCKS_BASE_URL=https://api.fireblocks.io
FIREBLOCKS_API_PATH=/v1
PORT=3000
```

### Running the Application

```bash
# Development mode
npm run start:dev

# Production mode
npm run build
npm run start:prod
```

The service will start on `http://localhost:3000` (or the port specified in your `.env` file).

## API Endpoints

### POST /transactions

Creates a new transaction by proxying the request to Fireblocks API.

**Note**: Authentication headers (`X-API-Key` and `Authorization`) are automatically handled by the service using credentials from your `.env` file. You only need to send `Content-Type` and `Accept` headers.

**Request Body:**
```json
{
  "assetId": "XLM_USDC_T_CEKS",
  "source": {
    "type": "EXCHANGE_ACCOUNT",
    "id": "300d1b9a-f46b-4ee6-be99-659fcd3cd802"
  },
  "destination": {
    "type": "EXTERNAL_WALLET",
    "id": "56216a51-5fad-4433-ac89-d4416fad7c0d"
  },
  "amount": "1",
  "feeLevel": "MEDIUM",
  "note": "",
  "operation": "TRANSFER",
  "customerRefId": "payoutCircleExternal",
  "externalTxId": "circleTest"
}
```

**Response (200 OK):**
```json
{
  "id": "transaction-id",
  "status": "SUBMITTED"
}
```

**Error Responses:**

- **400 Bad Request**: Validation errors
  ```json
  {
    "statusCode": 400,
    "message": ["property should not exist"],
    "error": "Bad Request"
  }
  ```

- **502 Bad Gateway**: Fireblocks API errors
  ```json
  {
    "message": "Fireblocks API error",
    "code": 1001
  }
  ```

- **500 Internal Server Error**: Internal errors
  ```json
  {
    "message": "Failed to create transaction",
    "code": "REQUEST_ERROR"
  }
  ```

## Authentication

The service implements Fireblocks JWT authentication using RS256 signing. The authentication flow follows Fireblocks API specifications exactly.

### JWT Token Structure

The JWT token is generated by `FireblocksAuthService` and includes the following claims:

- **`uri`**: The exact API endpoint path (e.g., `/v1/transactions`). This must match the endpoint being called exactly, including the `/v1` prefix.
- **`nonce`**: A random 32-character hexadecimal string generated for each request
- **`iat`**: Issued at timestamp (Unix epoch in seconds)
- **`exp`**: Expiration timestamp (30 seconds after `iat`)
- **`sub`**: Your Fireblocks API Key (must exactly match the value in `FIREBLOCKS_API_KEY` environment variable)
- **`bodyHash`**: SHA256 hash of the raw HTTP request body as a JSON string (hex encoded)

### Authentication Headers

Each request to Fireblocks includes:

- **`X-API-Key`**: Your Fireblocks API Key (same value as `sub` claim in JWT)
- **`Authorization`**: Bearer token containing the JWT (format: `Bearer <jwt_token>`)
- **`Content-Type`**: `application/json`
- **`Accept`**: `application/json`

### Critical Implementation Details

1. **URI Claim**: The `uri` claim in the JWT must exactly match the API endpoint path:
   - For `POST /transactions`: `uri = "/v1/transactions"`
   - The path includes the `/v1` prefix and the endpoint path

2. **BodyHash Calculation**:
   - The `bodyHash` is calculated from the exact JSON string that will be sent in the HTTP request body
   - Uses `JSON.stringify()` to ensure consistent serialization
   - The body is sent as a string to prevent Axios from re-serializing it differently
   - Any difference in JSON formatting (spaces, key order, etc.) will cause authentication to fail

3. **Sub Claim**:
   - Must use the exact API Key value from `FIREBLOCKS_API_KEY` environment variable
   - This value must match the `X-API-Key` header
   - The private key file must be the one paired with this specific API Key

4. **Private Key Handling**:
   - The private key is loaded from the file specified in `FIREBLOCKS_SECRET_KEY_PATH`
   - The key is automatically cleaned to remove:
     - Byte Order Mark (BOM) if present
     - Extra whitespace at start/end
     - Inconsistent line endings (normalized to `\n`)
     - Extra blank lines
   - Must be in PEM format with `-----BEGIN PRIVATE KEY-----` or `-----BEGIN RSA PRIVATE KEY-----` markers

### Error Handling

When Fireblocks returns an authentication error (code `-7`), the service provides detailed troubleshooting information:

- Verification checklist for API key and private key pairing
- Format validation guidance
- URI and bodyHash matching requirements
- Header alignment confirmation

### Example Request Flow

1. Request body is serialized to JSON string: `JSON.stringify(transactionData)`
2. BodyHash is calculated: `SHA256(bodyString).digest('hex')`
3. JWT payload is constructed with `uri: "/v1/transactions"`, `sub: <apiKey>`, `bodyHash: <hash>`
4. JWT is signed with RS256 using the private key
5. HTTP request is sent with:
   - URL: `https://api.fireblocks.io/v1/transactions`
   - Headers: `X-API-Key`, `Authorization: Bearer <jwt>`
   - Body: The exact JSON string used for bodyHash calculation

## Environment Variables

| Variable | Description | Default |
|----------|-------------|---------|
| `FIREBLOCKS_API_KEY` | Fireblocks API key (required) | - |
| `FIREBLOCKS_SECRET_KEY_PATH` | Path to your Fireblocks private key file (`.key` file) | `./fireblocks_secret.key` |
| `FIREBLOCKS_BASE_URL` | Fireblocks API base URL | `https://api.fireblocks.io` |
| `FIREBLOCKS_API_PATH` | Fireblocks API path | `/v1` |
| `PORT` | Server port | `3000` |

**Important**:
- Place your `fireblocks_secret.key` file in the project root (or specify the path in `FIREBLOCKS_SECRET_KEY_PATH`)
- Make sure the `.key` file is in your `.gitignore` to avoid committing it
- The private key file should be in PEM format (standard RSA private key format)
